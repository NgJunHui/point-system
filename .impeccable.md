## Design Context

### Users
A host running a group activity (party games, class games, team-building). They're standing up,
phone or laptop in hand, calling out results while people wait. Jobs: split a list of names into
N roughly-equal teams, award points to whole teams fast, fix one person's score, reshuffle between
games while scores carry over.

### Brand Personality
Quiet, native, quick. It should feel like a built-in Apple utility: no branding, no decoration,
nothing that competes with the room. Confidence comes from speed and zero mistakes, not visuals.

### Aesthetic Direction
- Apple system UI: system font stack (SF on Apple devices, Segoe UI Variable on Windows),
  inset grouped surfaces, segmented control, stepper, tinted buttons, iOS-style alerts.
- Light and dark, following the OS.
- Single centered column, no nav or footer.
- Color is functional only: system blue for actions, system red for destructive. Teams are
  named Team 1, Team 2, … with a small Apple system-colour dot as a secondary marker.

### Design Principles
1. Every in-game action is one tap. Awarding points never asks for confirmation; it offers Undo instead.
2. Anything that destroys or reshuffles data asks first with an iOS-style alert.
3. Show what changed: numbers that move get a brief pulse.
4. Nothing on screen that the host doesn't use during a game.
